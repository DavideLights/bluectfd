# Update Context Across Project Chats

Use this skill to autonomously synthesize and update `context.md` with cross-chat intelligence, discovered runtime parameters, active environments, and progress across all chat sessions in the project workspace.

Each chat session in Antigravity has isolated memory, but all conversations for a workspace share the underlying project. This skill ensures that decisions, VM configurations, API tokens, service startup scripts, and test findings produced in any chat are centralized in `context.md` for all present and future chats to consume.

--------------------------------------------------------------------------------

## When to Run This Skill

1. **Explicit User Command**: Whenever the user asks to "update context.md", "sync chats", "what did the other chat do?", or runs `/update-context`.
2. **Session Kickoff**: When beginning a new task in a project workspace, to ingest the latest cross-chat environment state and avoid duplicate work.
3. **Milestone Completion**: After deploying a service, discovering environment credentials (e.g. SSH targets, API tokens, ports), executing test plans, or implementing architectural modifications.

--------------------------------------------------------------------------------

## Agent Execution Steps

### Step 1: Run Automated Context Extraction

Execute the synchronization helper script located in the skill directory:

```bash
python3 .agents/skills/update-context/scripts/sync_context.py --workspace .
```

*Options available:*
- `--workspace <path>`: Specifies project root (defaults to CWD).
- `--context-file <path>`: Overrides target output file (defaults to `<workspace>/context.md`).
- `--limit <n>`: Number of recent chats to analyze (defaults to 10).
- `--dry-run`: Previews the generated markdown in stdout without writing.
- `--dump-json`: Outputs raw extracted conversation data as JSON.

### Step 2: Verify & Enrich `context.md`

1. Open and inspect `<workspace>/context.md`.
2. Review the `<!-- BEGIN CROSS-CHAT SYNC -->` block generated by the script:
   - **Discovered Infrastructure & Runtime Parameters**: Check that IPs, SSH credentials, tokens, and active ports from recent chats are properly reflected.
   - **Multi-Chat Session Directory**: Verify that all active chats in the workspace are cataloged.
   - **Detailed Cross-Chat Activity & Progress Log**: Ensure the summary accurately captures recent developments.
3. If your current session discovered unique architectural insights, error resolutions, or specific test logs that benefit other agents, add or refine those details directly in `context.md`.
4. Ensure the markers `<!-- BEGIN CROSS-CHAT SYNC -->` and `<!-- END CROSS-CHAT SYNC -->` remain intact so future updates can merge seamlessly.

### Step 3: Inform the User

Provide a concise, clickable summary to the user:
- Total number of project chats synchronized.
- Newly discovered runtime assets (e.g., VM IPs, active ports, auth tokens, scripts).
- Link to the updated [context.md](file:///home/davidel/blueagent/context.md).
